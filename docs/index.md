# 막혔을 때

AWS 클라우드 입문 실습 도움말입니다. 화면에 보이는 문구로 내 칸을 찾아 「왜」와 「고치기」를 읽어 보세요.

## 막혔을 때 순서

1. 이 페이지에서 지금 하는 단원을 찾습니다. 화면의 오류 문구를 복사해 브라우저 찾기(Ctrl+F)에 넣어도 됩니다.
2. 5분쯤 해 봐도 안 되면 화면을 그대로 두고 손을 듭니다. 오류 메시지는 지우지 마세요. 오류 메시지가 가장 좋은 단서입니다.
3. 손을 들면 좌석 번호, 단원 번호, 화면의 오류 문구를 말해 주세요.

**늦어도 괜찮습니다.** 막힌 단계는 강사가 완성 상태로 맞춰 줍니다. 다음 단원은 모두 같이 시작합니다.

## 어느 단원에서나

### 리전은 서울

콘솔 오른쪽 위 리전이 **서울**(ap-northeast-2)인지 먼저 봅니다. 수업 계정은 서울 밖을 막아 두어서 다른 리전에서는 목록이 비거나 빨간 권한 오류가 뜹니다.

<a id="values"></a>
### 수업 계정에서 되는 값

이 밖의 값을 고르면 권한 오류로 거부됩니다.

| 무엇 | 되는 값 |
|---|---|
| EC2 인스턴스 유형 | `t3.micro`, `t3.small`. 서울의 기본값 `t2.micro` 는 거부됩니다 |
| EBS 볼륨 | 하나에 30GB 이하 |
| RDS | 엔진 MySQL, 클래스 `db.t3.micro` 또는 `db.t4g.micro`, 단일 AZ, 스토리지 20GB 이하. Aurora 는 만들 수 없습니다 |
| NAT 게이트웨이 | 만들 수 없습니다 |
| 액세스 키 | 만들 수 없습니다. 서버에서는 IAM 역할을, 브라우저에서는 CloudShell 을 씁니다 |
| 비싼 서비스 | SageMaker, Bedrock, EKS 같은 서비스는 막혀 있습니다 |

### 수업에서 쓰는 이름

| 단원 | 이름 |
|---|---|
| 4단원 | 역할 `guestbook-ec2-role`, 서버 `guestbook-1` |
| 7단원 | 버킷 `guestbook-좌석번호-아무숫자` (예: `guestbook-s01-1104`) |
| 9단원 | 공지 버킷 `guestbook-notice-좌석번호-숫자` |
| 10단원 | `guestbook-vpc`, 서브넷 `public-a`(2a)와 `public-c`(2c), `guestbook-igw`, `guestbook-public-rt` |
| 11단원 | 시작 템플릿 `guestbook-lt`, 보안 그룹 `guestbook-web`, 서버 `guestbook-2` |
| 12단원 | `guestbook-tg`, `guestbook-alb`, `guestbook-alb-sg`, `guestbook-asg` |
| 13단원 | 함수 `guestbook-hello` |

### 권한 오류 읽는 법

빨간 오류 상자에서 아래 문구를 찾아보세요. 3단원에서 연습한 읽기입니다.

- **`explicit deny in a service control policy`**: 수업 계정이 막아 둔 일을 했습니다. 리전이 서울인지, [되는 값](#values) 밖을 고르지 않았는지 봅니다.
- **`because no identity-based policy allows`**: 아직 권한을 주지 않았습니다. 서버에서 난 오류라면 그 서버의 IAM 역할에 필요한 정책을 붙입니다(9단원).
- **`Encoded authorization failure message`** 만 보이면: 이유가 암호처럼 감춰진 메시지입니다. 화면을 그대로 두고 손을 드세요. 강사가 메시지를 풀어 봅니다.
- **`403` `Forbidden`** 만 보이면: 같은 대상의 목록 보기(예: `aws s3 ls`)를 해 보면 이유가 적힌 메시지가 나옵니다.

<a id="http"></a>
### http 주소가 안 열릴 때

서버, S3 웹사이트, 로드 밸런서 주소는 `http://` 입니다. 주소창에 IP 나 이름만 넣으면 Chrome 이 `https://` 로 바꿔 열다가 시간 초과가 납니다.

**[고칠 것] 「사이트에 연결할 수 없음」「응답하는 데 시간이 너무 오래 걸립니다」 `ERR_TIMED_OUT` `ERR_CONNECTION_TIMED_OUT`**
- 왜: 브라우저가 주소를 https 로 바꿔 열었습니다. 우리 앱은 http 로만 열려 있습니다.
- 고치기: 그 탭은 닫고 새 탭에 `http://주소` 를 직접 입력합니다. 실패한 탭에서 고쳐 치면 계속 실패할 수 있습니다.

**[정상입니다] 「이 사이트는 보안 연결을 지원하지 않습니다」**
- 「사이트로 이동」을 누르면 열립니다. 주소창의 「주의 요함」도 http 라서 뜨는 표시입니다.

### 무시해도 되는 화면

- 콘솔 첫 화면의 안내 말풍선: 닫고 시작합니다.
- Session Manager 화면의 Chrome 번역 말풍선: 닫습니다.
- S3 권한 탭의 「현재 이 계정의 퍼블릭 액세스 차단 설정이 활성화됨」: 계정의 ACL 차단 안내입니다. 버킷 설정만 바꾸면 됩니다.
- IAM 역할 화면의 「access-analyzer:ListPolicyGenerations에 대한 액세스 거부됨」: 이 수업에서 쓰지 않는 칸이라 그대로 둡니다.
- 요금(결제) 화면이 열리지 않음: 수업 계정에서는 막혀 있을 수 있습니다.

<a id="u1"></a>
## 1단원 콘솔 로그인

첫 로그인은 사용자 이름 → 쪽지의 일회용 비밀번호 → MFA 등록 → 새 비밀번호 → 포털 순서입니다.

**[고칠 것] MFA 유형 화면에서 「다음」이 눌리지 않습니다**
- 왜: 처음에는 아무 유형도 골라져 있지 않습니다.
- 고치기: 세 번째 **「인증 앱」**을 고릅니다.

**[고칠 것] 「기본 제공 인증자」를 골라 등록했습니다**
- 왜: 이 방식은 지금 쓰는 PC 에 묶여서 다음 날 다른 PC 에서 들어오지 못합니다.
- 고치기: 손을 드세요. 강사가 등록을 지우면 다음 로그인에서 「인증 앱」으로 다시 등록합니다.

**[고칠 것] 인증 앱의 6자리 숫자를 넣어도 계속 틀립니다**
- 왜: 휴대폰 시계가 어긋나면 숫자가 맞지 않습니다.
- 고치기: 휴대폰 설정에서 날짜와 시간 **자동 설정**을 켜고 새로 나온 숫자를 넣습니다.

**[고칠 것] 인증 앱을 설치할 수 없습니다**
- 왜: 보호자 승인을 기다리거나 스토어 비밀번호를 모르거나 학교 와이파이가 내려받기를 막는 경우입니다.
- 고치기: 6자리 숫자를 만드는 인증 앱(Google Authenticator, Microsoft Authenticator 등)이 이미 있으면 그 앱을 씁니다. 모바일 데이터로 받아도 됩니다. 그래도 안 되거나 휴대폰이 없으면 손을 드세요. 강사 예비 기기로 등록하고 수업을 이어 갑니다.

<a id="u3"></a>
## 3단원 일부러 거부당하기

**[정상입니다] 도쿄에서 EC2 → 「인스턴스」를 열면 빨간 오류가 뜹니다**
- 화면: `You are not authorized to perform this operation. ... is not authorized to perform: ec2:DescribeInstances with an explicit deny in a service control policy`
- 이 오류를 읽는 것이 이 단원의 실습입니다. 메시지에서 `not authorized` 와 `explicit deny` 를 찾은 뒤 서울로 돌아옵니다.

**[정상입니다] 도쿄에서 인스턴스 시작 마법사를 열면 「AMI ID(…)가 유효하지 않습니다」, 「VPC를 찾을 수 없습니다」가 뜹니다**
- 도쿄에서는 조회가 막혀서 생긴 오류입니다. 원인 문구가 보이지 않으니 실습은 「인스턴스」 목록의 오류로 합니다.

**[정상입니다] 서울로 돌아오면 인스턴스 목록이 비어 있습니다**
- 아직 만든 서버가 없어서입니다. 빨간 오류가 없으면 됩니다.

**[정상입니다] CloudShell 의 `aws sts get-caller-identity` 결과에 `AWSReservedSSO_` 가 보입니다**
- 로그인 포털이 만들어 준 역할로 들어와 있다는 뜻입니다.

<a id="u4"></a>
## 4단원 EC2 시작과 Session Manager

**[고칠 것] 정책 이름을 검색했는데 문서 검색 결과만 나옵니다**
- 왜: 화면 맨 위의 콘솔 검색창에 넣었습니다.
- 고치기: 역할 만들기의 권한 단계에서 **권한 정책 표 바로 위의 검색칸**에 `AmazonSSMManagedInstanceCore` 를 넣습니다.

**[고칠 것] 인스턴스 시작이 `You are not authorized to perform this operation` 으로 실패합니다**
- 왜: 인스턴스 유형이 서울의 기본값 `t2.micro` 그대로이거나 리전이 서울이 아닙니다. 뒤에 `Encoded authorization failure message` 가 붙을 수 있습니다.
- 고치기: 유형을 `t3.micro` 로 바꾸고 다시 시작합니다.

**[고칠 것] 연결 화면에서 「연결」을 눌렀는데 실패합니다**
- 왜: 처음 골라진 카드가 「EC2 인스턴스 연결」입니다. 이 방식은 SSH 22 포트가 필요합니다.
- 고치기: 카드 네 개 가운데 **「SSM Session Manager」** 카드를 고르고 「연결」을 누릅니다.

**[고칠 것] 「SSM Session Manager」의 「연결」 버튼이 회색입니다**
- 왜: 서버가 막 켜졌으면 등록까지 1~2분 걸립니다. 그보다 오래 회색이면 서버에 역할이 없거나 퍼블릭 IP 가 없는 경우가 많습니다.
- 고치기: 1~2분 기다리고 새로고침합니다. 그래도 회색이면 인스턴스 → 작업 → 보안 → **IAM 역할 수정**에서 `guestbook-ec2-role` 을 붙이고 몇 분 기다립니다. 인스턴스에 퍼블릭 IPv4 주소가 있는지도 봅니다.

**[정상입니다] 까만 화면에 `sh-5.2$` 가 보입니다**
- 접속에 성공했습니다. `bash` 를 한 번 입력하면 익숙한 셸이 됩니다. 접속한 사용자는 `ssm-user` 입니다.

<a id="u5"></a>
## 5단원 공통 앱 배포와 서비스 등록

**[정상입니다] 첫 창에서 Ctrl+C 를 누르거나 창을 닫으면 앱이 같이 꺼집니다**
- 다음 장에서 서비스로 등록해 고칩니다.

**[고칠 것] `systemctl status guestbook` 이 `active (running)` 이 아닙니다**
- 왜: 앞에서 직접 띄운 앱이 아직 80 포트를 잡고 있으면 서비스가 뜨지 못합니다.
- 고치기: 앱을 띄운 첫 창에서 Ctrl+C 로 앱을 끄고 `sudo systemctl restart guestbook` 합니다.

**[정상입니다] `systemctl status` 화면에서 명령을 칠 수 없습니다**
- 내용을 넘겨 보는 화면입니다. `q` 를 누르면 나옵니다. `--no-pager` 를 붙이면 바로 끝납니다.

**[정상입니다] `sudo reboot` 뒤 세션 창이 끊깁니다**
- 30초쯤 뒤 연결 화면에서 다시 「연결」합니다.

**[정상입니다] 브라우저로 서버 주소를 열면 안 열립니다**
- 6단원에서 보안 그룹을 열기 전에는 정상입니다. 서버 안에서 `curl localhost` 로 확인합니다.

<a id="u6"></a>
## 6단원 보안 그룹으로 공개

**[고칠 것] 「사이트에 연결할 수 없음」 `ERR_CONNECTION_TIMED_OUT`**
- 왜: Chrome 이 주소를 https 로 바꿔 열었습니다.
- 고치기: [http 주소가 안 열릴 때](#http)를 봅니다.

**[고칠 것] 새 탭에서 `http://주소` 로 열어도 안 열립니다**
- 왜: 인바운드 규칙이 없거나 앱이 꺼져 있습니다.
- 고치기: 보안 그룹 인바운드 규칙에 사용자 지정 TCP, 포트 `80`, 소스 `0.0.0.0/0` 이 있는지 봅니다. 서버에서 `systemctl status guestbook` 도 확인합니다.

**[정상입니다] 인바운드 규칙에 SSH 22 규칙이 이미 있습니다**
- 4단원 시작 마법사가 만든 규칙입니다. 80 규칙만 더하면 됩니다.

<a id="u7"></a>
## 7단원 S3 정적 웹사이트

**[고칠 것] 「버킷 정책 변경 사항을 저장할 수 없습니다. 버킷 정책을 편집할 권한이 없거나 버킷 정책이 퍼블릭 액세스 차단 설정과 충돌하는 퍼블릭 액세스 수준을 부여합니다.」**
- 왜: 권한 문제처럼 보이지만 버킷의 퍼블릭 액세스 차단이 아직 켜져 있습니다.
- 고치기: 권한 탭에서 퍼블릭 액세스 차단을 편집해 「모든 퍼블릭 액세스 차단」 체크를 끄고 저장합니다. 입력란에 `확인` 을 넣은 뒤 버킷 정책을 다시 저장합니다.

**[정상입니다] 권한 탭에 「현재 이 계정의 퍼블릭 액세스 차단 설정이 활성화됨」이 보입니다**
- 계정의 ACL 차단 안내입니다. 버킷 설정만 끄면 됩니다.

**[고칠 것] 정적 웹사이트 호스팅이 저장되지 않습니다**
- 왜: 인덱스 문서 칸의 `index.html` 은 흐린 예시일 뿐 값이 비어 있습니다.
- 고치기: 칸에 `index.html` 을 직접 입력하고 저장합니다.

**[고칠 것] 버킷 이름이 받아들여지지 않습니다**
- 왜: 버킷 이름에는 소문자, 숫자, 하이픈만 쓸 수 있습니다.
- 고치기: `guestbook-s01-1104` 처럼 짓습니다. 「버킷 네임스페이스」는 기본값(글로벌) 그대로 둡니다.

**[정상입니다] 웹사이트 주소를 열면 「이 사이트는 보안 연결을 지원하지 않습니다」가 뜹니다**
- 웹사이트 주소도 http 입니다. 「사이트로 이동」을 누릅니다.

<a id="u8"></a>
## 8단원 퇴실 전 서버 중지

**[고칠 것] 「인스턴스 중지」와 「인스턴스 종료(삭제)」 중 무엇을 누를지 헷갈립니다**
- 왜: 중지는 끄기, 종료는 버리기입니다. 종료한 서버는 다시 켤 수 없습니다.
- 고치기: 인스턴스 행을 체크하고 인스턴스 상태 → **인스턴스 중지** → 확인 창의 「중지」를 누릅니다.

**[정상입니다] 확인 창에 「연결된 Elastic IP 주소와 EBS 볼륨에 대한 요금은 계속 청구됩니다」가 보입니다**
- 중지해도 디스크 요금은 남는다는 안내입니다. 그대로 「중지」를 누릅니다.

**[고칠 것] 실수로 종료했습니다**
- 고치기: 손을 드세요. 강사가 다음 단원에 필요한 상태로 맞춰 줍니다.

<a id="u9"></a>
## 9단원 IAM 역할로 S3 읽기

**[고칠 것] 어제 서버를 켜려는데 새 서버 만들기 화면이 열리거나 「인스턴스 상태」 메뉴가 회색입니다**
- 왜: 오른쪽 위 주황 「인스턴스 시작」은 새 서버를 만드는 버튼입니다. 목록을 새로 열면 행 체크도 풀립니다.
- 고치기: `guestbook-1` 행을 체크하고 **인스턴스 상태 → 인스턴스 시작**을 누릅니다.

**[정상입니다] 다시 켠 서버의 퍼블릭 IP 가 어제와 다릅니다**
- 중지했다가 켜면 공인 IP 가 바뀝니다. 12단원에서 로드 밸런서 주소를 쓰는 이유입니다.

**[정상입니다] `aws s3 ls` 가 `An error occurred (AccessDenied) when calling the ListObjectsV2 operation: ... because no identity-based policy allows the s3:ListBucket action` 으로 거부됩니다**
- 서버 역할에 아직 S3 권한이 없어서입니다. 이 거부를 읽고 권한을 붙이는 것이 이 단원의 실습입니다.
- `aws s3 cp` 는 `An error occurred (403) when calling the HeadObject operation: Forbidden` 만 냅니다. 원인은 같습니다.
- 다음: IAM → 역할 → `guestbook-ec2-role` → 권한 추가 → 정책 연결 → `AmazonS3ReadOnlyAccess`. 15초쯤 뒤 같은 명령이 됩니다. 재접속이나 재부팅은 필요 없습니다.

**[고칠 것] 정책을 붙였는데 방명록 화면에 공지가 안 보입니다**
- 왜: 앱이 어느 버킷을 읽을지 아직 모릅니다.
- 고치기: `sudo nano /opt/guestbook/config.env` 로 열어 `NOTICE_BUCKET=공지버킷이름` 을 적고(저장 Ctrl+O, 나가기 Ctrl+X) `sudo systemctl restart guestbook` 합니다.

**[고칠 것] 역할에 권한을 주기 전인데도 공지가 읽힙니다**
- 왜: 7단원의 공개 버킷에 올렸습니다. 공개 버킷은 역할 없이도 읽혀서 거부 장면이 나오지 않습니다.
- 고치기: 퍼블릭 액세스 차단을 켠 채로 새 버킷 `guestbook-notice-좌석번호-숫자` 를 만들어 `notice.txt` 를 올립니다.

<a id="u10"></a>
## 10단원 VPC 직접 만들기

**[고칠 것] CIDR 칸에 흐린 `10.0.0.0/24` 가 보입니다**
- 왜: 흐린 글씨는 예시이고 칸은 비어 있습니다.
- 고치기: VPC 칸에는 `10.0.0.0/16` 을 직접 입력합니다. 서브넷은 2a 에 `10.0.1.0/24`, 2c 에 `10.0.2.0/24` 를 넣습니다.

**[고칠 것] 리소스 맵에서 서브넷, 라우팅 테이블, 게이트웨이가 선으로 이어지지 않습니다**
- 왜: 연결 단계 하나가 빠졌습니다.
- 고치기: 아래 넷을 차례로 봅니다.
  1. 인터넷 게이트웨이 `guestbook-igw` 가 `guestbook-vpc` 에 연결됐는지
  2. `guestbook-public-rt` 라우팅에 `0.0.0.0/0` → 인터넷 게이트웨이가 있는지
  3. 그 라우팅 테이블에 두 서브넷이 연결됐는지
  4. 두 서브넷 모두 「퍼블릭 IPv4 주소 자동 할당」이 켜졌는지(서브넷마다 따로 켭니다)

**[정상입니다] 라우팅 편집 화면의 두 칸 이름이 모두 「대상」입니다**
- 왼쪽 칸에 `0.0.0.0/0` 을 넣고, 오른쪽 칸에서 「인터넷 게이트웨이」를 고른 뒤 `igw-` 목록에서 `guestbook-igw` 를 고릅니다.

**[고칠 것] 「VPC 등」 마법사로 만들다가 NAT 게이트웨이에서 실패합니다**
- 왜: 수업 계정은 시간당 요금이 붙는 NAT 게이트웨이를 막아 둡니다.
- 고치기: 「VPC만」을 골라 하나씩 만듭니다. 마법사가 반쯤 만든 자원은 15단원에서 같이 지웁니다.

<a id="u11"></a>
## 11단원 시작 템플릿으로 새 VPC 에 서버

**[고칠 것] 템플릿 칸이 모두 「시작 템플릿에 포함하지 않음」입니다**
- 왜: AMI, 인스턴스 유형, 키 페어, 서브넷, IAM 인스턴스 프로파일 칸이 「시작 템플릿에 포함하지 않음」으로 시작합니다. 그대로 두면 빈 템플릿이 됩니다.
- 고치기: AMI 는 Quick Start → Amazon Linux, 인스턴스 유형은 `t3.micro`, 고급 세부 정보 → IAM 인스턴스 프로파일은 `guestbook-ec2-role` 로 고르고 사용자 데이터 칸에 대본을 붙여 넣습니다.

**[고칠 것] 템플릿으로 시작할 때 서브넷 `public-a` 에 시작되지 않습니다**
- 왜: 템플릿의 「보안 그룹 생성」 VPC 칸 기본값이 기본 VPC 입니다.
- 고치기: 보안 그룹의 VPC 칸을 `guestbook-vpc` 로 바꿔 템플릿을 다시 만듭니다.

**[정상입니다] 「인스턴스 시작」을 누르면 키 페어 대화 상자가 다시 뜹니다**
- 「키 페어 없이 계속 진행」을 고르고 대화 상자 안의 「인스턴스 시작」을 한 번 더 누릅니다.

**[고칠 것] 새 서버의 방명록이 안 열립니다**
- 왜: 앱을 설치하는 데 1~2분 걸립니다. 그보다 오래 걸리면 사용자 데이터 대본이 중간에 멈췄을 수 있습니다.
- 고치기: 1~2분 기다린 뒤 새 탭에 `http://공인IP` 로 엽니다([http 주소가 안 열릴 때](#http)). 몇 분이 지나도 안 열리면 그 서버에 Session Manager 로 접속해 `sudo tail -n 30 /var/log/cloud-init-output.log` 로 어디서 멈췄는지 봅니다.

**[정상입니다] 새 서버 방명록에 「아직 글이 없습니다」가 보입니다**
- 어제 쓴 글은 어제 서버의 디스크 파일에 있습니다. 미니 프로젝트의 DynamoDB 메뉴가 이 문제를 풉니다.

<a id="u12"></a>
## 12단원 로드 밸런서와 오토 스케일링

**[고칠 것] 앞에서 만든 대상 그룹이나 서브넷이 다음 화면 목록에 안 보입니다**
- 왜: 대상 그룹, 로드 밸런서, 보안 그룹 생성, 오토 스케일링 그룹 화면의 VPC 칸 기본값이 모두 기본 VPC 입니다.
- 고치기: 화면마다 VPC 칸을 `guestbook-vpc` 로 바꿨는지 봅니다.

**[고칠 것] 새로 만든 보안 그룹이 로드 밸런서 화면에 안 보입니다**
- 왜: 「보안 그룹 생성」은 새 탭으로 열리고 VPC 칸이 기본 VPC 로 채워져 옵니다.
- 고치기: 새 탭에서 VPC 를 `guestbook-vpc` 로 바꾸고 HTTP 위치 무관 규칙으로 만듭니다. 로드 밸런서 탭으로 돌아와 보안 그룹 새로 고침을 누른 뒤 고릅니다.

**[고칠 것] 로드 밸런서 주소가 계속 안 열립니다**
- 왜: 처음 골라진 `default` 보안 그룹은 같은 그룹끼리만 허용해서 인터넷에서 들어오지 못합니다.
- 고치기: 로드 밸런서 보안 그룹에서 `default` 를 지우고 HTTP 를 연 보안 그룹만 남깁니다. 주소는 새 탭에 `http://` 를 붙여 엽니다.

**[정상입니다] 만든 직후 `502 Bad Gateway` 가 나오거나 새 서버가 `Unhealthy`(Health checks failed)로 보입니다**
- 서버가 사용자 데이터로 앱을 설치하는 중입니다. 로드 밸런서가 활성이 되기까지 2분쯤, 새 서버가 `Healthy` 가 되기까지 2분 30초쯤 걸립니다. 서버 하나를 종료한 뒤 새 서버가 `Healthy` 가 되기까지는 5분쯤 걸립니다.

**[고칠 것] 몇 분이 지나도 계속 `Unhealthy` 입니다**
- 왜: 서버 보안 그룹이 로드 밸런서에서 오는 80 포트를 막고 있거나 상태 검사 경로가 틀렸습니다.
- 고치기: 서버 보안 그룹(11단원 `guestbook-web`)에 HTTP 80 이 열려 있는지, 대상 그룹 상태 검사 경로가 `/health` 인지 봅니다.

## 13단원 서버리스 맛보기

**[고칠 것] 「함수 생성」 버튼이 보이지 않습니다**
- 왜: 콘솔 화면이 바뀌어 메뉴 이름이 「Event Functions」, 만들기 버튼이 「Create Event Function」입니다.
- 고치기: 「Create Event Function」을 누릅니다. 「지속적인 실행」, 「EC2 용량 공급자」 토글은 끈 채 둡니다. 만든 뒤 「Getting started」 창이 덮으면 「Dismiss」로 닫습니다.

**[고칠 것] 런타임이 Node.js 로 되어 있습니다**
- 왜: 런타임 기본값이 Node.js 이고 Python 목록은 순서가 뒤섞여 있습니다.
- 고치기: 목록에서 **Python 3.13** 을 찾아 고릅니다.

**[고칠 것] 코드 편집기에 붙여 넣기가 안 됩니다**
- 왜: Chrome 이 「클립보드를 공유하시겠습니까?」라고 물을 때 「차단」을 눌렀습니다.
- 고치기: 주소창 왼쪽의 사이트 정보 아이콘에서 클립보드를 「허용」으로 바꾸고 새로고침합니다. 코드를 손으로 한 줄씩 치면 자동 들여쓰기가 겹쳐 코드가 망가지니 붙여 넣습니다.

**[고칠 것] Deploy 버튼이 사라졌습니다**
- 왜: 편집기 왼쪽 「DEPLOY」 구역 제목을 눌러 구역이 접혔습니다.
- 고치기: 「DEPLOY」 제목을 다시 눌러 펼칩니다. Test 를 처음 누르면 이벤트 만들기 화면이 열리니 이름을 아무거나 넣고 주황 「Test」를 누릅니다.

**[고칠 것] API 주소를 열면 `{"message":"Not Found"}` 가 나옵니다**
- 왜: 주소 앞부분만 열었습니다.
- 고치기: 주소 끝에 `/default/guestbook-hello` 를 붙입니다. 트리거 화면에 나온 주소 전체를 엽니다.

## 15단원 정리

**[정상입니다] 오토 스케일링 그룹이 몇 분째 「삭제 중」이고 서버가 실행 중으로 보입니다**
- 삭제에 5분쯤 걸립니다. 기다리지 말고 다음 줄(로드 밸런서와 대상 그룹 삭제)로 넘어갑니다.

**[고칠 것] 삭제 창의 삭제 버튼이 눌리지 않습니다**
- 왜: 창마다 입력해야 하는 확인 문구가 다릅니다.
- 고치기: 창 안의 문구를 그대로 입력합니다. 서비스마다 다릅니다.
  - 오토 스케일링 그룹: `삭제`
  - 로드 밸런서: `확인`
  - S3 비우기: `영구적으로 삭제`
  - S3 버킷 삭제: 버킷 이름
  - RDS: `delete me`
  - CloudShell: `delete`

**[고칠 것] 삭제가 거부됩니다**
- 왜: 다른 자원이 아직 쓰고 있는 것은 지워지지 않습니다. 서버가 남아 있으면 VPC 가 지워지지 않고, 버킷은 비워야 지워집니다.
- 고치기: 오류 메시지가 알려 주는 자원부터 지웁니다. 정리 장의 순서(만든 순서의 반대)를 따릅니다.

**[고칠 것] RDS 삭제 창에 「최종 스냅샷 생성」이 켜져 있습니다**
- 왜: 켜 둔 채 지우면 스냅샷이 남아 요금이 붙습니다.
- 고치기: 체크를 끄고 새로 나오는 「자동화된 백업을 더 이상 사용할 수 없다는 점을 인정합니다」를 체크한 뒤 `delete me` 를 입력합니다.

**[정상입니다] 파라미터를 지우자 「정품 인증이 성공적으로 삭제되었습니다.」가 뜹니다**
- 번역이 틀린 안내입니다. 파라미터는 지워졌습니다.

**[정상입니다] Lambda 함수를 지웠는데 API 와 역할이 남아 있습니다**
- 함수를 지워도 API 와 실행 역할은 남습니다. API 는 API Gateway 에서, 역할은 IAM 역할 목록에서 따로 지웁니다. 4단원 보안 그룹 `launch-wizard-1` 도 EC2 → 보안 그룹에서 따로 지웁니다.
